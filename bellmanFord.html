§ 01 — Overview

What is Bellman-Ford?

Bellman-Ford is a single-source shortest path algorithm conceived by Richard Bellman and Lester Ford Jr. in the 1950s. Unlike Dijkstra's algorithm, it handles graphs with negative edge weights and can detect the existence of negative weight cycles.

The algorithm works by progressively relaxing edges — repeatedly updating the shortest known distance to each vertex. After |V| − 1 passes through all edges, we are guaranteed to have found all shortest paths (assuming no negative cycle exists).

🔗

Edge Relaxation

For each edge (u, v, w), if dist[u] + w < dist[v], we update dist[v]. This "relaxes" our estimate closer to the true shortest path.

🔁

V − 1 Iterations

A shortest path in a graph with V nodes can contain at most V − 1 edges. Running V − 1 rounds of relaxation guarantees convergence.

⚠️

Negative Cycle Detection

Running one extra (V-th) round reveals negative cycles: any distance that can still be reduced indicates a negative weight cycle exists.

🌐

Works on Directed Graphs

Bellman-Ford handles directed graphs naturally. It is used in distance-vector routing protocols like RIP, and in financial arbitrage detection.

§ 02 — How It Works

Step-by-Step Walkthrough

The algorithm follows a clear, methodical structure. Click each phase to understand what happens at every stage.

Initialization

Set the source node's distance to 0. All other nodes are initialized to positive infinity (∞), meaning they are currently unreachable.

We also initialize a predecessor array to track the shortest-path tree, which lets us reconstruct the actual path after the algorithm completes.

Source node
dist[S] = 0
All other nodes
dist[v] = ∞

Edge Relaxation

For every edge (u → v) with weight w, we check: is dist[u] + w < dist[v]? If yes, we found a shorter path to v through u — so we relax the edge and update dist[v].

This is the core operation. One iteration processes all edges in the graph once, potentially improving many distance estimates simultaneously.

// Relax edge (u → v, weight w)
if dist[u] + w < dist[v]:
  dist[v] = dist[u] + w
  prev[v] = u

Repeat V − 1 Times

A shortest path through a graph of V nodes can use at most V − 1 edges (otherwise it would revisit a node, forming a cycle).

By repeating the full edge relaxation pass V − 1 times, we propagate shortest distances across paths of increasing length — guaranteeing that every shortest path is found.

After iteration k, all shortest paths using at most k edges are correctly computed.

Negative Cycle Detection

After V − 1 iterations, run one extra pass. If any edge (u, v, w) can still be relaxed — meaning dist[u] + w < dist[v] — then a negative weight cycle is reachable from the source.

In such a cycle, traversing the loop indefinitely keeps decreasing the total path cost, so no finite shortest path exists for affected nodes.

⚠ Negative cycle detected!
// dist[v] still decreasing after V−1 rounds

BELLMAN-FORD

  • Handles negative edge weights
  • Detects negative weight cycles
  • Works on directed & undirected graphs
  • Simpler implementation
  • Slower: O(VE) vs O((V+E) log V)
  • Not suitable for large, dense graphs

DIJKSTRA'S

  • Much faster with a priority queue
  • Optimal for non-negative weights
  • Used in GPS, game pathfinding
  • Fails with negative edge weights
  • Cannot detect negative cycles
  • Requires non-negative weights strictly
§ 06 — Real-World Applications

Where It's Used

Bellman-Ford's unique ability to handle negative weights makes it indispensable in several critical domains.

01 —

Network Routing (RIP)

The Routing Information Protocol uses a distributed form of Bellman-Ford to compute shortest paths across network hops, with each router maintaining a distance-vector table.

02 —

Currency Arbitrage

Log-transforming exchange rates into negative weights lets Bellman-Ford detect arbitrage opportunities — cycles where trading currencies yields a profit.

03 —

Traffic Engineering

Road networks with toll credits or reward segments (negative weights) can be modelled and optimally routed using Bellman-Ford.

04 —

Constraint Solving

Difference constraint systems in scheduling and verification reduce to finding shortest paths; Bellman-Ford determines feasibility or finds an optimal assignment.

05 —

Distributed Systems

Its iterative, asynchronous nature makes Bellman-Ford naturally suitable for distributed shortest-path computation where no single node has full graph knowledge.

06 —

Game AI & Simulation

In game worlds where terrain bonuses (negative costs) exist — like magical terrain or power-ups — Bellman-Ford correctly computes the "cheapest" path.
